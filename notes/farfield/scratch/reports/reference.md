## 1. The pinned volume formula (item 4)

Let the source cell be centred at the origin and the target cell at
`R = (D1 s1, D2 s2, D3 s3)`, both with edges `s = (s1,s2,s3)`; `V_t = s1 s2 s3`;
`k = 2 pi f`; Gila's scalar kernel

    g(r) = exp(2 pi i f r) / (4 pi f^2 r) = e^{ikr} / (4 pi f^2 r).

Difference box `D_box = prod_i [-s_i, s_i]`, triangle weight `w(delta) = prod_i (s_i - |delta_i|)`.
Then the tensor that `srfSum!` assembles from `srfMat[fp] = (int_F int_F' g dS' dS) / V_t`
is, for every separated pair,

    G_gila[a,b](R) = (1/V_t) int_{D_box} w(delta) [ (d_a d_b + delta_ab k^2) g ](R + delta) d delta
                   = (1/V_t) int_{D_box} w(delta) [ (d_a d_b - delta_ab lap) g ](R + delta) d delta.

Sign: **+1 on both the diagonal and the off-diagonals**, with **no** extra factor of
`k^2`, `4 pi`, `f^2` or `V_t` beyond the ones written (the `1/(4 pi f^2)` sits inside `g`,
the `1/V_t` is the target-cell average).  Derivation of that sign from `srfSum!`:
with `sigma_F = +-1` the normal sign and `c(F)` the face axis, `fp = 6(F-1)+F'`,
faces ordered `yzL yzU xzL xzU xyL xyU`,

    int_Vt int_Vs d_a d_b g = - sum_{c(F)=a, c(F')=b} sigma_F sigma_F' I_{FF'}    (a != b),

and `srfSum!`'s `G[1,2] = -s3+s4+s9-s10` is exactly that minus sign applied to
`sigma_F sigma_F' = (+,-,-,+)` for `(F,F') = (1,3),(1,4),(2,3),(2,4)`.  For the diagonal the
same rule gives `G[1,1] = -(1/V_t) int int (d_2 d_2 + d_3 d_3) g = (1/V_t) int int (d_1 d_1 - lap) g`,
and `lap g = -k^2 g` off the origin.

Second derivatives used by `volTensor` (`x = R + delta`, `r = |x|`):

    g'  = (i k - 1/r) g,    g'' = (i k - 1/r) g' + g / r^2,    lap g = g'' + 2 g'/r = -k^2 g,
    d_a d_b g = (g'' - g'/r) x_a x_b / r^2 + delta_ab g'/r.

Relation to the physical operator: Gila's operator is `4 pi^2` times the double cell average of
`(1/k^2)(grad grad - I lap) G_s`, `G_s = e^{ikr}/(4 pi r)`; since `4 pi^2 / k^2 = 1/f^2`,
`4 pi^2/k^2 * G_s = g`, which is why no `1/k^2` survives in the formula above.

Numerical pinning (all four sign conventions tested per offset: `(+diag,+off)`,
`(+diag,-off)`, `(-diag,+off)`, `(-diag,-off)`).  Table in section 3.

## 2. `ref.jl`: API, cache and usage

`SCRATCH/work/reference/ref.jl` — standalone, no Gila dependency; it `include`s
`notes/moments/moments.jl` (for `facePair`) and `notes/gen/ref/mom.jl` (for `pairKer`).

    refPairs(D::NTuple{3,Int}, s::NTuple{3,Rational{BigInt}}, f::Complex{BigFloat};
             prec = 220, ord = 44, cache = true) -> Vector{Complex{BigFloat}} (36 entries)
        srfMat[fp] = (int_F int_F' g dS' dS) / V_t,  fp = 6(F-1) + F', faces yzL yzU xzL xzU xyL xyU.
    refSum(sm) -> 3x3 Matrix          # the srfSum! signs
    refTensor(D, s, f; prec = 220, ord = 44, cache = true) -> 3x3 Matrix{Complex{BigFloat}}
    volTensor(D, s, f; prec = 220, ord = 32, cache = true) -> 3x3 Matrix{Complex{BigFloat}}
        the independent volume-volume rule of section 1.
    SUMIDX[a,b] -> Vector{Int}        # the face pairs summed into entry (a,b), for amplification

`volTensor` splits every axis of `D_box` at 0 (the triangle weight has a kink there, giving
8 sub-boxes), and inside each sub-box grades a tensor Gauss-Legendre rule of order `ord`
geometrically towards the corner nearest the singularity at `delta = -R`: the first panel has
width `dmn/2` where `dmn` is the distance from that sub-box to `-R`, and panel widths double
outward.  Nodes and weights are generated by Newton iteration on the Legendre recursion in
`BigFloat` (`glNodes`), so nothing in the rule is Float64.

Usage:

    include("ref.jl"); setprecision(BigFloat, 220)
    Q = Rational{BigInt}
    s = (Q(1)//32, Q(1)//32, Q(1)//32)
    Gref = refTensor((5, 1, 0), s, Complex{BigFloat}(1))          # 36 pairKer + srfSum! signs
    Gvol = volTensor((5, 1, 0), s, Complex{BigFloat}(1); ord = 32) # independent volume rule
    maximum(abs, Gvol .- Gref) / maximum(abs, Gref)                # 4.61e-64

Cache: `SCRATCH/refcache/reftensors.txt`, append-only, one record per line,

    <kind>|D=d1,d2,d3|s=n1//d1,n2//d2,n3//d3|f=<re>;<im>|p=<prec>|n=<ord>|<v1> <v2> ...

`kind` is `pairs` (36 values, the scaled face-pair integrals) or `vol` (9 values, the volume
tensor in column-major order); each value is `<re>;<im>` printed by `string(::BigFloat)` at the
record precision, so it round-trips exactly.  A reader tracks its byte offset and only parses up
to the last newline, so it is safe to read while another process appends.

`max|G_ref|`; `vsRef` = max entry difference from `refTensor` (36 x pairKer + srfSum!), same
normalization.  Criterion "doubling the order changes nothing at 1e-40".

Reading the coarse-cell tables: **the amplification is a fine-cell effect.**  At lambda/4 the
signed sum of the 36 face pairs loses only a factor 5 to 163 (5 to 7 for the face and body
diagonals at every separation), at lambda/8 a factor 14 to 326, at lambda/32 a factor 34 to 1300.
The reason is that `srfMat[fp]` scales as the face-pair integral over `V_t` while the tensor entry
is a second difference; the second difference is a factor `~(s/R)^2` smaller than the terms, so the
amplification grows like `(R/s)^2 = n^2` at fixed cell size only along directions where the entry
decays fastest (the axis entry `G[1,1]` at an axis offset: 36 -> 1300 from 2 to 64 cells at
lambda/32, 5 -> 163 at lambda/4).  Along the body diagonal it is constant (312 at lambda/32,
20 at lambda/8, 5 at lambda/4).

Two further facts visible only in the coarse tables:
- At lambda/4 and lambda/8 the *per-pair* error of Gila's rule grows with separation along the
  axis direction (c4: 8.5e-15 at 2 cells to 1.0e-13 at 64 cells; c8: 6.7e-15 to 7.6e-14).  This is
  not quadrature error, it is the phase rounding of the far kernel: a relative eps in `r` is an
  absolute phase error `2 pi f r eps`, and at 64 cells of 1/4 wavelength `r = 16`, `2 pi * 16 * eps
  = 2.2e-14`.  It is invisible at lambda/32 where `r <= 1.1`.
- The assembled tensor at lambda/4 is *more* accurate than at lambda/32 (1.6e-15 to 2.8e-13 versus
  5.0e-14 to 8.7e-13), because the low amplification more than compensates the larger per-pair error.
